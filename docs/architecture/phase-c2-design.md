## 状态与取舍

采用纯选择器 + reducer + Hook，复用 C1。相比把阶段塞入旧事件 index，此方案能保留独立专题顺序；相比新增全局跨专题时间轴，它不需要推断尚无证据的跨专题顺序。不会新增全局历史排序字段、第二套体验状态机或完成记录。

- C 的 timeline 模块唯一持有 selectedTopicId/activePhaseId/playing，支持选择、前后、播放、暂停、专题重播与恢复；初始选择按专题 displayOrder 的导航顺序取首个合法专题及其首阶段。这只是默认浏览入口，不是跨专题历史先后。
- 只消费 createExperienceCatalog 的 getPublishedDatasetV2 视图。Topic.phaseIds 必须与各 phase.topicId/sequence 严格一致；异常拒绝播放，不能自行重排。4 秒仅为展示间隔，不生成时间、速度或地理位置。
- 有合法阶段时，阶段时钟是唯一宏观自动计时器；旧 usePlayback 只保留事件选择/兼容投影，计时被禁用。没有阶段数据时允许旧事件回放；空数据仍禁用。暂停、数据撤回、失焦及隐藏不累计墙上时间。
- 初始、数据变化及运行中撤回均先投影合法状态再呈现，拒绝迟到 tick。最后阶段停止，不跨专题循环。专题重播不触碰 C1 完成记录。

## 对象与上下文

专题抽屉采用专题→阶段→事件的按需展开目录，附关联人物、地点和全局资料目录；所有对象详情仍走 C1 唯一入口。选择专题/阶段只改变探索，不调用重点体验入口。明确点击事件才进入 C1。

当前专题、阶段、对象选择和合法相机书签共同形成探索上下文。C1 内部 ExplorationContext 向后兼容增加可选 topicId；退出/完成后按当前发布视图恢复，保持暂停。阶段变化清理旧选择和旧书签；未知/已撤回上下文不强行恢复。无坐标地点继续可从目录阅读。

嵌套目录明确选择另一个阶段的事件时，先以该目录的已发布 topic/phase 作为入口上下文；地图或正文关联导航不根据名称/日期猜阶段，保持当前上下文。普通关闭、取消选择、返回首页与体验退出继续各自独立。

## 部队与地图

selectForceStateForPhase 只选当前已发布阶段及已发布 track/snapshot/route 的匹配关系。按 point/region/route 原显示模式提供已有几何，缺输入则隐藏，不把两个端点连线，不把 region 当精确点，不把图标数当兵力。

地图 v2 沿用现有 props。传入的 dataset 是发布数据的当前阶段空间视图：部队、路线、可定位地点和事件仅保留本阶段关联；完整发布目录仍由 C 的 catalog 提供阅读。它是只读显示投影，不写回、也不作为正式 JSON 再验证。图例由同一份可见态势派生，宏观示意持续标注，未显示的模式不伪称已绘制。

没有 A v2 出口时保留旧场景和合法空状态，不复制 Three.js 场景。C0 schema 与公共 props 不变，空间视图语义与 A/B 接线在接口文档中说明。
