## 生产数据与资源隔离

`virtual:history-release` 在构建时完整校验唯一原始 dataset.json，输出发布视图和仅含 event/topic/experience 稳定 ID、阶段声明布尔值的 deny-only 索引。App 默认消费安全快照。其他原始 dataset.json 的生产导入也重定向为发布视图，带 raw/url 查询的原始模块若进入产物则被模块检查拒绝。

deny-only 索引保留 C1 重点体验门槛和 C2 阶段系统声明：撤回体验不会降级成普通阅读，旧完成记录不能重新开放；撤回阶段不会恢复旧 v1 自动时钟。该索引没有草稿正文、互动答案、来源全文或图片路径，只能收紧访问。

生产禁用 public 整目录复制，仅输出：既有壳字体与三份许可文件，以及经过 C0 闭合发布过滤允许的素材。文件必须存在于 public 实际边界内；保留原来全部引用、双人复核与 rightsStatus 门槛。未来合法发布素材在隔离临时工程的正向构建测试中可进入输出。

B 的图片、sidecar、哈希、生成说明和审核记录全部原地保留，无迁移、删除或字段提升。生产检查同时覆盖实际文件名、模块 ID、JS/HTML/JSON 内容、原始资源来源及未发布资源字节哈希，图片改名后也会失败。旧生产模块隔离插件继续运行，并扩展拒绝 history review 及 A 开发 UI 模块。

实际负向构建验证了候选脚本泄露和改名图片泄露会失败；实际预览 HTTP 测试验证首页 200，开发工作台、B 审阅 HTML、unknown 人物图路径 404。生产静态部署需要沿用“仅部署 dist”的边界，不能把仓库 public 或 A 独立展示包额外上传。
