## 全景渲染替换边界

`src/app/panorama/map-renderer.ts` 的 `PanoramaMapAdapter` 是本次 C 容器的技术边界：

- `focus(bounds)`：区域视窗平滑推进，不是行军或地图路线插值。
- `overview(top?)`、`zoom(direction)`：全景、俯瞰及缩放。
- `bookmark()` / `restore(bookmark)`：`sceneId='long-march-modern-panorama'`，scene-local position/target，不是历史经纬度。
- `setRoutes(routes,camps)`：仅接收 C 已发布且按阶段筛选的路线；`unitId` 保留多支主力区分；没有合法数据就空。
- `setRivers(visible)` / `suspend(value)` / `dispose()`：图层、局部入口暂停绘制和完整资源释放。
- 首帧真实渲染后才回报本地图 ready；不得借此触发 C1 的体验 ready。

后续 A 从 `src/features/scene/index.ts` 提供正式全景 `LongMarchSceneV2`，C 将容器对接该公共出口，不能跨模块导入 A 内部文件。上面的原型适配器不替代既有 v2 契约；若需扩展书签 sceneId／视图参数，先由 C 更新文档、消费者和测试。

## 四渡赤水优先细化

阶段 ID 固定为 `sd-phase-1` 至 `sd-phase-4`；候选详情分别对应 `event-sd-1` 至 `event-sd-4`。不能把专题总述代替各阶段卡。四个阶段共用一个赤水流域取景框，不生成四个虚假渡口坐标。

目前演示板是独立**非地理**拓扑，坐标范围 0..100，红虚线／蓝点线、箭头、队伍图标只演示图层角色和阶段切换，不是对真实四渡战术的复原。正式地图仍为 0 条已核路线，不能把该工程板贴到真实河流上。

下一批必须协调 B 提供：每渡的渡口/地点证据、原始坐标系与精度、红军分部队路线分段、国军部队与有证据的阶段位置／区域、明确先后和来源。缺失几何保持 null/hidden；已知地点之间不能自动连线。C2 `scene-phase-view` / `force-state` 仍是唯一正式阶段空间输入。

1. 以本轮现代地形和统一坐标为参考，提出全景 LOD 与水墨材质方案；保留垂直夸张和现代数据标注。

文档可由用户直接交给 A；本轮没有通过消息工具自动向 A 发送内容。

## 预览后用户明确的视觉方向

- 保留真实现代底图的相对格局，允许山体高度、河流显示宽度与镜头尺度艺术夸张；不能因此移动或补造历史坐标／行军线。
- 事件镜头要更贴近、角度更低。当前 C 原型提供 1×/6×/12×/24× 高度和更近的平滑取景；高倍率下粗网格仍有棱面，需要 A 的全景 LOD、地形材质、山水光雾细化。
- 点击事件呈现大幅艺术题字；出现期间收起旧浮窗与资料，点击题字后恢复。`CinematicTitle.tsx` 是可复用的 C 界面层，字体及 OFL 来源在 `assets/font-provenance.json`。
- 右侧标题与浮动标志已做初步视觉层次，但最终按钮、资料与时间轴必须回到原“立即进入”后的探索容器。不要另造一个脱离展馆的最终页面。
