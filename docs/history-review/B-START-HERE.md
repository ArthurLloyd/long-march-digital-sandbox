# B 交付包：先看这里

版本 b-draft-1.1.0；适用基线 `78c315ae92ba55b09ae12e2cad87fd281c4b8801`。

本包代码在下载的 ZIP 中，尚未放到你的 Windows 项目，也没有自动推送 GitHub。本包是累积交付，包含上一包内容，直接使用这一包即可。它包含 B 范围的代码、六主题候选、5组人物照片与艺术形象、来源、测试和交接文件。

## 第一步：放到项目

按 B-INSTALL.md 合并复制 `src`、`docs`、`public` 的具体文件到原仓库，保留原 `.git`、其他源码和本地修改。不删除原目录，不复制 node_modules 或 Node 程序。包内没有修改 A/C 代码。

## 第二步：直接看六专题与人物图

在 PowerShell 执行：

```powershell
cd D:\Competition\long-march-digital-sandbox
$env:Path = "D:\Competition\node-v24.22.2-win-x64;" + $env:Path
npm.cmd run dev
```

保持终端运行，浏览器打开：

`http://127.0.0.1:5173/src/features/history/review/index.html`

若终端给的端口不同，用实际端口替换5173。这个地址是新加的 **本地候选审阅页**；首页地址仍按原来的正式审核门槛展示。

- 左侧六主题：浏览各自正文、五段剧本和两项互动。
- “事件全文”的下拉框：还可看四渡阶段卡、安顺场及决议通过等补充阅读，共12条。
- “五段体验与互动”：先读本段，完成实际操作，再确认解释、继续；最后主动完成本次审阅。
- “人物与照片”：五位人物各有照片、生成图、年代、出处和放大链接；黄开湘仅文字。
- “地点与阶段”“来源与使用条件”：核对地点、日期、文献定位与局限。

本页进度只在内存中，刷新或切换专题会重置，不保存展馆通关，不伪造审核记录。

## 第三步：查看交付和检查结果

- B-DELIVERY.md：B0—B3逐项产出和未完成验收。
- B-CHECKS.md：真实测试、构建结果及当前1项C旧断言问题。
- B-PORTRAIT-ASSETS.md：10个图像文件的来源、AI制作方法与待核点。
- B-SPATIAL-HANDOFF.md：给A的阶段、双方单位、地点与不可补造的空间缺口。
- 各 `*-content-pack.md`：六份可独立交给A/C的全文、字幕、互动材料与解释。
- C-TEST-HANDOFF.md：供C评审的三行测试补丁，未自动应用。

你现在可以先看效果并检查文字。确认代码后再按 B-INSTALL.md 提交到 `feat/history-system`，创建PR交C集成。照片使用条件、史实双人复核和A/C联合验收未结束前，不能把候选包当成可公开部署的比赛最终版。
