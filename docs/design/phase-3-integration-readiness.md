## 计划顺序与每步停止条件

1. **B 的事件组件**：先提供独立小PR，保留公共出口和props；验证null、长段落、多个来源、来源局限、关闭回调、键盘阅读。不要引入第二套全局事件选择状态。
2. **B 的正式数据**：另交来源与审核记录。逐条核对真实人员双人复核链接及发布范围；校验通过后才进入正式入口。有争议记录保持unpublished，不用虚构内容填空。
3. **A 的三维场景**：独立PR接入既有场景容器；首次可交互报告ready，无WebGL／资源失败报告error；卸载释放监听、定时器、GPU对象。先验空数据，不依赖真实路线才能启动。
4. **已审核节点与路线**：确认坐标系、空间精度、几何证据与solid/points/dashed/hidden规则。不插值连接已确认地点。地图及地形使用条件另核查。
5. **选择、镜头与时间轴联动**：核对用户点节点、章节选择、前后、播放／暂停、关闭资料和返回首页。事件顺序由B的核验数据决定，C不为动画更改排序。相机实现归A。
6. **展示录制**：多尺寸视觉复验、错误降级和素材条件确认后再录制；展示未完成的部分时明确开发状态，不放宽史料门禁。

每一步：fetch并阅读对应PR → 检查所有权与类型diff → 使用契约测试和真实页面检查 → 记录问题 → 本地六项检查与CI → 负责人决定是否合并。不要直接把双方整分支一次性覆盖到本地。
