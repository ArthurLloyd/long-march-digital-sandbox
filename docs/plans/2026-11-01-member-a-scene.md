# 成员 A 独立任务书：三维地图、部队态势与沉浸场景

日期：2026-11-01。交付对象：成员 A 及其 Codex。本文包含整体目标、个人任务、接口依赖、GitHub 操作和开工提示词，可以独立转发。

## 一、任务总览与当前基线

作品“长征·不灭的火种”完成后的主线是：进入展馆 → 操作立体地图 → 按历史阶段查看红军／国民党军态势 → 点击事件、地点、人物 → 重点事件首次完成沉浸互动 → 阅读正文 → 返回同一地图位置继续探索。

用户已确认：每个重点事件分别记录首次完成状态，保存在当前浏览器；完成后再次点击直接看文字，可主动重播。普通事件、地点、人物直接进入资料。人物动漫形象需要搭配真实照片。

互动名单也已确认：遵义会议、四渡赤水、巧渡金沙江、飞夺泸定桥、翻越雪山、穿越草地，六项全部规划，泸定桥先打样。每项两个必要互动与五类剧情段落详见本文末尾 EXP-1.0 同版附录。

你的责任是三维呈现、相机、态势显示动画和重点事件渲染器。B 负责历史依据、阶段和剧本；C 负责公共接口、选择状态、首次体验门槛、本地记忆和全局 UI。对应[总方案](2026-11-01-master-plan.md)。

GitHub 仓库：[ArthurLloyd/long-march-digital-sandbox](https://github.com/ArthurLloyd/long-march-digital-sandbox)。[PR #3](https://github.com/ArthurLloyd/long-march-digital-sandbox/pull/3) 已合入 main，已核对基线为 `417d02e76f86d24d255e17b3e77d8f7c381ecea4`；随后以最新 `origin/main` 为准，不回退 main。你的跟踪 Issue 是 [#1](https://github.com/ArthurLloyd/long-march-digital-sandbox/issues/1)，开发分支是 `feat/3d-scene`。

现状：展馆应用壳已存在，真实三维渲染尚未接入；正式数据仍为 0 事件／0 路线／0 来源。已有测试与 CI 通过不代表真实 WebGL、地形和本轮新功能已验收。

## 三、A0：立即并行的小样

在等待 C0 新契约期间，可以先做：

1. **相机与地形工程小样**：拖动、旋转、平移、缩放、复位，验证标签点击和相机操作不会互相抢事件。
2. **沉浸场景工程小样**：一个河谷／桥体类场景、预设镜头、可环顾视角、一个暂停等待点击的节点、继续及退出回调。首个历史样板确定为“飞夺泸定桥”，工程小样仍不能凭空填入真实战斗细节；正式闭环需完成附录中的 ld-01、ld-02 两个互动。
3. **可行性报告**：实际画面、设备、视口、加载情况、帧率／帧耗时、资源规模、瓶颈和降级效果。小样以约一分钟的演绎作为设计预算，最终时长由审核剧本决定。

工程小样与 fixtures 仅放隔离测试／开发入口，不由生产代码导入。正式数据为空时，主入口保持诚实的空态。若需应用中的专用预览入口，交 C 接线；不能为了演示直接向正式 dataset 填假节点。

交付 A0 后立即开小 PR，附可运行方式和真实证据。不要先等待全国地形、全部战役模型或全部 B 数据到齐。

## 四、A1：可操作的立体地图

### 地形与视觉

- 采用“宏观全览＋重点区域”的两级细节。全览看清山脉、河谷、主干水系及事件分布；近看重点区域，增加局部细节。
- 用户参考图说明立体地形厚度、斜俯视、地名与事件标牌的层次；不是边界、地形或路线的数据源。保持作品墨蓝、朱红、暗金视觉，不能把 UI 标签排满地图。
- 有来源的 DEM／高度图生成网格；山体起伏不能用随机噪声冒充真实地理。河流、道路、桥梁的历史位置和形态由 B 证据约束。
- 地形需要垂直夸张时，登记系数并注明展示处理，标记和镜头使用同一变换。不能用夸张后的模型推导历史海拔或距离。
- 原始资料记录坐标系、投影、高程基准、覆盖范围、获取日期、许可证及处理过程；世界坐标变换必须只有一套可复现实现，不能混用屏幕坐标、WGS84 和现代偏移坐标。
- 大型原始 DEM、扫描图或未确认素材不直接塞进 Git。先提供范围、大小和处理方案；提交必要的衍生资源及来源说明。

现代地形只能作为候选基底，不能证明历史地貌未变。[USGS SRTM 产品说明](https://www.usgs.gov/centers/eros/science/usgs-eros-archive-digital-elevation-shuttle-radar-topography-mission-srtm-1)供数据选型研究；实际取用及地图展示条件由团队针对具体素材核查。

### 操作与标签

- 鼠标与触摸支持旋转、平移、缩放；限制合理的近远距离与俯仰角，防止钻入地下或把场景拖出可恢复范围。
- 提供“恢复全览／复位视角”能力。近距离显示更多细节，全览减少标签；当前选中对象优先显示，不被遮挡。
- 事件、地点、人物的热点外观有区分；无地理位置的对象仍可由 C 的目录访问，不强行放上地图。
- 真实坐标统一来自数据输入；标签点击只回调对象 ID。避免三维对象与 DOM 标签一次点击触发两次导航。
- 进入体验前可以输出可序列化的相机书签；退出后按 C 指令恢复。书签是场景局部坐标状态，不是历史坐标。

相机基本能力参见 [Three.js OrbitControls](https://threejs.org/docs/pages/OrbitControls.html)。

## 五、A2：全览中的部队动态态势

输入来自 B 的已发布单位、阶段样本和路线，不是 A 手写的战争轨迹。

| 输入证据                   | 允许显示                                     | 不允许的处理                                           |
| -------------------------- | -------------------------------------------- | ------------------------------------------------------ |
| 有完整几何、阶段和顺序依据 | 原几何逐段显现、箭纹流动、沿原几何的显示动画 | 平滑或改写路线，补出缺失段，声称动画速度是真实行军速度 |
| 只有已确认阶段位置         | 对应阶段位置标记、淡入／淡出                 | 连接两点当作实际行军线，沿猜测曲线移动图标             |
| 有依据的宏观示意           | schematic 虚线，并持续标明性质               | 伪装为精确实线或省略示意说明                           |
| 身份、时间或位置证据不足   | 隐藏，交 C/B 显示资料缺口                    | 自动选最近城镇、现代道路或 AI 生成位置                 |

双方部队都有稳定 ID、明确范围和阶段。不同层级、不同红军部队不能并成一条“全体红军路线”。图标、箭头密度和动画粒子数量不代表兵力。阵营采用颜色加符号／线型及清晰图例，不仅靠红蓝区分。

C 的历史阶段是唯一宏观时钟。前进、后退、重播和快速切阶段必须确定性一致；暂停后停止推进，返回前一阶段不残留未来图层。现有 `playbackProgress` 和 4 秒轮播不能直接当部队位置或真实时间。

## 六、A3：代码驱动的沉浸事件

主方案是实时三维演绎：场景对象、光照、环境、镜头和动画由代码调度，可在合理范围环顾；有脚本推进与必要互动。它不是已经存在的历史影像，也不等同于自动生成电影。

### 渲染器与脚本

- 使用 B 经审核的声明式 ExperienceManifest，按稳定段落 ID 推进；不在几何代码内硬编码史实文案、人物对话、日期或战斗结果。
- 镜头支持“预设推进＋观众环顾偏移”。不能因用户转头错过必要互动，也不让镜头飞出故事区域。暂停、失焦、返回与减少动态均有处理。
- 到达必要互动点时停止剧情推进，通知 C。互动 UI 由 C 组合 B 的公共组件；A 不导入 B 内部文件，也不自己维护全局通关记录。
- 用户选择只影响查看材料、观察顺序或教学反馈；真实历史行动主线及结局固定。未经核验的人物对白、命令、动作细节不编造。
- 场景重建明确标注为艺术演绎；程序生成的雾、水和群众剪影是表现手段，不作为当时天气、精确人数或个人行为的证据。
- 对缺少史料依据的局部采用克制、抽象表现，并在脚本说明局限，不补成写实“复原”。

### 与 C 的回调边界

拟通过 `src/features/scene/index.ts` 新增沉浸渲染器公共出口，最终名字与 props 由 C0 固化。语义至少包括：

- 输入：已发布脚本、当前段落、播放／暂停、画质、减少动态与当前互动状态。
- 输出：ready、error、到达段落、请求互动、到达结尾、请求退出、相机书签。
- “到达结尾”仅上报事实；C 校验必要互动并呈现“完成体验，阅读资料”按钮，用户激活后才记录完成。
- 退出／报错不能发成功完成回调。重播、快速开关、同一事件再次进入不能重复触发结束事件。

保留当前 `LongMarchScene` v1 出口及回调兼容。在 C0 合并前不要自行扩展公共 contracts 或正式根数据结构；可以交模块内部原型与字段提案。

### 性能与资源

- 全览与沉浸场景按需切换，避免两个重型画布在后台同时满速渲染；纹理、材质、几何可复用。
- 根据设备选择细节层次、像素比、阴影和粒子数量；移动低画质仍能完成剧情与互动。
- 以桌面稳定 30fps 为首轮规划目标、争取更高帧率；移动低档也以稳定可操作为目标，记录实测而非宣称所有设备达标。
- 卸载释放控制器、监听器、定时器、音频和实际应释放的 GPU 对象；共享资源不误销毁。后台暂停不能在恢复时跳过互动。
- 字幕和互动由 DOM 承载；WebGL 失败时通知 C 使用等价分步体验。

[R3F 性能指导](https://r3f.docs.pmnd.rs/advanced/scaling-performance)作为实现参考。全景显示可研究 [Three.js 示例](https://threejs.org/examples/webgl_panorama_equirectangular.html)，不要把示例照片当作项目素材。视频录制只是后续可选项，不把“导出任意设备 MP4”作为本轮承诺。

## 八、GitHub 同步和提交

第一次克隆（先接受私有仓库邀请）：

```powershell
git clone https://github.com/ArthurLloyd/long-march-digital-sandbox.git
cd long-march-digital-sandbox
git switch -c feat/3d-scene
npm ci
```

已有仓库：先进入自己的实际仓库目录，检查 `git status`，把本人已有修改提交到本人分支并确认干净，再按情况选择：

```powershell
# 已有本地功能分支
git fetch origin
git switch feat/3d-scene
git merge origin/main
npm ci
npm run dev
```

```powershell
# 尚无功能分支
git fetch origin
git switch main
git pull --ff-only origin main
git switch -c feat/3d-scene
npm ci
npm run dev
```

若只有远程同名分支，先检出并跟踪该分支，再合并 origin/main；不要强制重建同名分支。发生冲突时保留差异，与文件负责人一起解决，不覆盖他人工作。

每次提交前实际运行：

```powershell
npm run lint
npm run typecheck
npm run test
npm run validate:data
npm run build
npm run format:check
```

只 `git add` 本次自己的明确文件，使用 `feat(scene): ...` 等提交信息，`git push -u origin feat/3d-scene`，创建目标为 main 的 PR 并关联 Issue #1。不要执行强制推送、硬重置、批量清理，也不要替 B/C 提交或自行合并 main。历史或地理证据无法确认时可交工程模块，相关内容保持 unpublished。

## 九、给 Codex 的完整开工提示词

### 2. 六个体验共同的硬标准

#### 2.1 内容与场景

每个体验至少有：背景／地点引入、环境与证据观察、历史进程、结果与意义、明确结尾五类内容；可按审核脚本细分镜头。每个体验有两个必要互动，必要性与 ID 写入声明式脚本。

主方案是代码驱动的实时三维场景、预设镜头与可环顾视角，支持暂停、字幕、静音、退出。剧本不是实时生成的历史；真实人物不编对白、命令、表演性动作或未经证据支撑的个人经历。

场景为艺术演绎，局部坐标、天气效果、声响、剪影和镜头节奏不成为历史证据。剧本需逐项区分已核事实、编辑解释、艺术表现、未知细节；未知不靠画面填成“复原”。

画面目标沿用墨蓝山河、朱红／暗金界面与有层次的立体空间。不能把只有静态背景加按钮的小样直接当作最终三维体验验收；A0 提供实际可操作小样，C 先验画面和性能，再复制机制。

#### 2.2 必要互动的统一完成规则

每个互动都有提示、操作区、当前状态、反馈／解释、证据入口及明确“继续”。观察热点需真的打开要求的材料；选择／排序题需提交尝试并确认解释。答错有反馈，允许重新操作或阅读正确解释后继续，不要求不断猜对才能退出。

观众的选择只影响观察顺序、资料展开和教学反馈。不能改变真实行动顺序、历史人物决定、战役结果或真实人员命运；不存在以不同选项生成不同真实结局。

每个体验的完成条件严格为：

1. 主线到达终点；
2. 该体验两个必要互动均完成并确认解释；
3. 观众激活“完成体验，阅读资料”；
4. C 验证匹配的 experienceId 和完成规则版本，再写当前浏览器记录并打开正文。

仅点击开始、观看一段时间、进入后台、错误、超时或退出，不算完成。宏观自动播放只变阶段和轻摘要，不自动拉起体验；首次门槛发生在用户主动打开重点事件时。

#### 2.3 退出、重播与可访问性

- 第一次未完成可以退出回沙盘，保留地图上下文；下一次仍从首次体验入口开始，首版不做跨会话剧情断点。
- 完成后再次点击直接正文；“重播体验”始终可选，重播退出不抹掉原完成记录。
- 打开体验暂停宏观历史时钟；退出／完成后宏观播放仍暂停，用户自行继续。临时打开人物／材料浮层只暂停当前剧情，不重置。
- 无 WebGL、资源故障、减少动态或需要无三维操作的用户，使用同一脚本的等价图文分步体验，保留两个必要互动与完成按钮。
- 热点均有键盘和文字列表替代；环顾不是唯一取得必要信息的方法。字幕不依赖声音，静音不影响完成。
- 没有已审核降级脚本时明确暂不可用，不能用空白页面、故障或“下一步”次数冒充完成。

**sn-01：查看地形与行进见闻。** 热点为 `sn-hotspot-terrain` 与 `sn-hotspot-account`，分别打开地形说明和历史材料。所有精确数值必须有据；当代照片拍摄条件不被当作历史天气。

**sn-02：辨别演绎效果。** 题目聚焦“程序生成的雪雾和背景音，能否单独证明当时确切天气／声响”。提交后解释场景效果与历史证据的区别，并链接本事件实际资料；确认解释后继续。

最小场景元素：来源明确的山体关系或清楚标注的局部艺术化环境、路径观察镜头、材料热点和字幕。不给观众设置会改写真实结局的体力、饥饿或死亡分支。

### 8. E06 穿越草地：环境与补给资料观察

experienceId：`exp-crossing-grasslands`。

| 段落           | 画面与操作                               | 内容标准                                     | 通过条件                       |
| -------------- | ---------------------------------------- | -------------------------------------------- | ------------------------------ |
| gr-s1 范围     | 具体部队、区域、时段与背景               | B 与雪山体验分别建档，避免范围混用           | 不是同一背景换贴图就算另一事件 |
| gr-s2 材料观察 | 环境与生活／补给材料两个观察点           | 对应原始材料或明确编辑说明                   | gr-01 两类材料查看完毕         |
| gr-s3 主线     | 克制的环境与行进视角，呈现核验内容       | 人物与困难叙述有来源；不靠随机数生成真实故事 | 不虚构真实人物生死、台词或行为 |

**gr-02：选择支持材料。** B 提供一条经核验的解释、一个对应史料选项和一个明确的艺术场景选项；观众提交后理解哪种材料能支持历史结论、哪种只能辅助感受，确认解释后继续。

### 9. 普通事件、地点、人物和完成后的正文

- 六主题之外的事件默认直接正文，除非后续明确增加重点体验并更新标准。
- 六主题关联子事件是否共用门槛由唯一映射规定；不能不同入口各弹一份重复体验。
- 地点正文包含历史名称、现代对照、事件关联、精度和材料性质；缺坐标仍可从目录访问。
- 人物动漫图必须与同一人的真实照片配对、分别说明与署源。无可用真实照片先文字展示并列缺口；不拿绘画／生成图伪装真实照片。
- 重点主题的正文必须独立完整：背景、经过、结果／影响、关联人物地点、来源及局限；体验完成后可直接读文，不依赖视频才能理解。
- 真实历史照片与当代纪念照片不混标；动漫／AI 图注明制作属性。使用条件不明的素材不发布。
