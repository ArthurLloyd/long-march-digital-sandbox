# 成员 B 独立任务书：史实资料、事件剧本、人物与教学互动

日期：2026-11-01。交付对象：成员 B 及其 Codex。本文包含作品总览、个人任务、内容标准、GitHub 步骤和开工提示词，可以独立转发。

## 一、作品目标与分工

完成版由立体地图承载历史探索：观众查看山川河谷和双方部队阶段态势，点击重点事件进入可环顾、可互动的剧情演绎，体验后阅读文字；普通事件、地点、人物直接打开资料。人物动漫形象与经核验、具使用条件的真实照片配对展示。

用户已确认“首次强制”的范围：每个重点事件分别完成一次，当前浏览器保存记录；完成后默认直达正文，可重播，换设备或清除数据后可能重新体验。固定历史主线不由观众的选项改变。

A 负责地图、相机与三维表现；你负责事实、资料、剧本、题目、人物和地点内容；C 负责公共接口、阶段调度、点击路由、首次门槛与记忆。对应[总方案](2026-11-01-master-plan.md)。

用户已确认六个互动主题全部规划：遵义会议、四渡赤水、巧渡金沙江、飞夺泸定桥、翻越雪山、穿越草地，泸定桥先打样。每项段落和两个必要互动详见本文末尾 EXP-1.0 同版附录；名单是产品范围，历史细节仍需你逐项核验。

## 三、B0：现在即可开始的内容准备

第一轮交一个“可行性与资料包”小 PR：

不需要先等 A 完成模型。资料不足的内容明确留缺口，优先交能支撑第一个闭环的内容。

## 五、每个事件必须交什么

### 事实与阅读包

1. 稳定 ID、标题、所属专题、关联事件及经核验的顺序。
2. 日期或范围及其精度，涉及部队／人物、历史地名、现代对照与局限；未知坐标为 null。
3. 一段短摘要和完整正文：背景 → 经过 → 结果／影响 → 与前后事件的联系。
4. 每项重要主张对应来源定位，编辑概述、原始摘引、艺术再现与教学模拟分清。
5. 关联图片、档案或音视频清单，逐项记录作者、机构、原链接或书目、使用条件、加工记录与分类。
6. 审核状态和争议清单。候选先 draft + unpublished，不预填“已审核”。

### 沉浸剧本包

| 项目                   | 填写要求                                                             |
| ---------------------- | -------------------------------------------------------------------- |
| experienceId / eventId | 稳定关联，不能换标题就生成另一份完成记录                             |
| 段落 ID 与顺序         | 可被 A/C 稳定引用；标明必经段落、互动点和终点                        |
| 观众看到的内容         | 景物、观察方向、镜头意图和视觉重点；与历史依据对应                   |
| 旁白与字幕             | 编辑讲述标为编辑概述；真实引文附准确出处，不虚构讲话／命令／家书     |
| 历史依据               | 关键细节对应来源、页码／时间码、支持范围和不确定性                   |
| 表现性补充             | 雾、水、光、剪影等明确属于艺术演绎，不能暗示精确天气、人数和实名行为 |
| 互动                   | ID、提示、选项、反馈、依据、必要与否、完成后去向                     |
| 完成规则               | 必要互动 ID、终点及等价分步体验规则；时间长度不作为唯一完成条件      |
| 降级脚本               | 同内容的字幕／图文段落和必要互动，低性能用户可真实完成               |
| 版本                   | 普通文字修订与完成规则变更区分，不能靠每次修文强迫用户重看           |

脚本是声明式内容，不能包含待执行的任意 JavaScript。镜头表现与历史事实分别记账：局部三维坐标是场景布置，不是历史地理坐标；不能把工程镜头轨迹写进历史路线数据。

## 六、互动的可用形式与固定主线

推荐先做两类中的一类，首个样板只需一至两个必要节点：

- **史料观察**：选择先看地图或档案，点开证据后获得解释，继续固定主线。
- **顺序／依据判断**：选出经资料支持的顺序或表述，展示理由与出处。

选项影响观察顺序、阅读内容和教学反馈，不影响历史人物的真实决策、重大事件进程或结果。不给真实人物编台词，不让观众通过选项制造不同战役结局。

必要互动的完成默认是“作出选择并确认看过解释”，答错可反馈、重试或读解释后继续，不设置永远答不对就无法退出的障碍。观众始终可以退出，未完成的事件下次仍进入首次体验。B 只发互动完成事件，最终通关和本地存储由 C 控制。

## 七、双方部队、时间与空间资料

每个单位需要稳定 ID、阵营、单位名称及适用时期；简称或编制变化要解释。不能把不同方面军或不同国民党军单位混成一股连续移动的“红方／蓝方”。

每个阶段样本至少交：

- phaseId、时间范围与精度、叙事顺序的依据。
- 对应 unitId、已确认位置／区域、坐标或 null、空间精度。
- 行动关系、已有路线 ID 或明确“只有地点证据”。
- 支持的 sourceIds、材料定位、争议与缺口、真实审核记录。
- 是否只能示意／隐藏，是否有资格绘制完整几何；不提供未经证据支撑的逐日位置。

双方数据都执行同样的门槛。现代路网、景点定位、直线连接、最短路径或 AI 推理不作为历史行军线。兵力数量、行进速度和精确时刻缺依据时保留未知；图标规模不得由 B 的猜测数字驱动。

A 可沿完整原几何做显示动画；缺失中间路线时只切换阶段位置。B 不为“动画顺滑”补历史坐标，也不能把 4 秒播放或模型尺度当真实时空数据。

## 八、人物动漫形象与真实照片

### 交付要求

- 人物名称、身份时期、简介、关联事件、可靠来源及同名消歧。
- 经核验的真实照片：确认画面中的人、原始出处、拍摄时间或未知、作者／机构、使用条件；注明是否为事件发生前后其他时期的肖像。
- 动漫形象：对应同一 personId，标注“艺术化形象”；若 AI 生成，再标注生成属性与制作记录，不能称历史照片。
- 两图同屏或同一资料面板中并列展示，配各自说明、来源及可放大入口。观众不需要猜哪张是真实材料。
- 若没有可用真实照片，先保留文字条目并列缺口，不发布只靠动漫冒充已配对的头像，不把纪念画或生成图当真实照片。是否采用明确标注的其他肖像材料，另由你与 C/用户确认。

### 制作边界

形象服务于人物识别与资料阅读，先完成头像／半身展示，不把每个人都做成高成本可表演三维角色。服装、标识、装备和年龄不能随意错置。生成／临摹图不伪造本人言行，不生成可被误认作真实档案的图像。

本任务书没有授权购买素材、订阅服务、上传私人资料或安装新工具。若需这类操作，说明具体成本、权限与替代方案；已经在当前工作会话获得的明确授权不重复询问。

## 九、地点与普通事件

地点条目包含历史名称、现代对照、相关事件、说明、地图精度、历史与当代照片的区分及来源。现代景点坐标不能直接充当历史位置证据。无可靠坐标时可以从目录阅读，不由 A 就近吸附到城镇。

普通事件不设首次体验门槛；内容结构与重点事件保持一致。重点事件完成后也必须有完整正文，不让观众只能反复看动画。正文与 A 的演绎共用同一组已核验事实，不出现文字与画面顺序矛盾。

拟新增人物／地点详情与互动组件仍从 `history/index.ts` 暴露，最终 props 由 C0 固化。B 不通过内部 import 操作场景、不直接打开全屏、不直接写 localStorage 或改变主时间轴。

## 十一、GitHub 开工与提交

首次克隆前由仓库所有者确认已邀请并接受私有仓库访问；使用 `.nvmrc` 指定的 Node.js 24 与 npm：

```powershell
git clone https://github.com/ArthurLloyd/long-march-digital-sandbox.git
cd long-march-digital-sandbox
git switch -c feat/history-system
npm ci
```

已有仓库先进入实际目录，检查 git status，提交本人已有工作并确认干净。已有功能分支执行：

```powershell
git fetch origin
git switch feat/history-system
git merge origin/main
npm ci
npm run dev
```

尚无功能分支执行：

```powershell
git fetch origin
git switch main
git pull --ff-only origin main
git switch -c feat/history-system
npm ci
npm run dev
```

### 2. 六个体验共同的硬标准

#### 2.1 内容与场景

每个体验至少有：背景／地点引入、环境与证据观察、历史进程、结果与意义、明确结尾五类内容；可按审核脚本细分镜头。每个体验有两个必要互动，必要性与 ID 写入声明式脚本。

主方案是代码驱动的实时三维场景、预设镜头与可环顾视角，支持暂停、字幕、静音、退出。剧本不是实时生成的历史；真实人物不编对白、命令、表演性动作或未经证据支撑的个人经历。

场景为艺术演绎，局部坐标、天气效果、声响、剪影和镜头节奏不成为历史证据。剧本需逐项区分已核事实、编辑解释、艺术表现、未知细节；未知不靠画面填成“复原”。

画面目标沿用墨蓝山河、朱红／暗金界面与有层次的立体空间。不能把只有静态背景加按钮的小样直接当作最终三维体验验收；A0 提供实际可操作小样，C 先验画面和性能，再复制机制。

#### 2.2 必要互动的统一完成规则

每个互动都有提示、操作区、当前状态、反馈／解释、证据入口及明确“继续”。观察热点需真的打开要求的材料；选择／排序题需提交尝试并确认解释。答错有反馈，允许重新操作或阅读正确解释后继续，不要求不断猜对才能退出。

观众的选择只影响观察顺序、资料展开和教学反馈。不能改变真实行动顺序、历史人物决定、战役结果或真实人员命运；不存在以不同选项生成不同真实结局。

每个体验的完成条件严格为：

1. 主线到达终点；
2. 该体验两个必要互动均完成并确认解释；
3. 观众激活“完成体验，阅读资料”；
4. C 验证匹配的 experienceId 和完成规则版本，再写当前浏览器记录并打开正文。

仅点击开始、观看一段时间、进入后台、错误、超时或退出，不算完成。宏观自动播放只变阶段和轻摘要，不自动拉起体验；首次门槛发生在用户主动打开重点事件时。

#### 2.3 退出、重播与可访问性

- 第一次未完成可以退出回沙盘，保留地图上下文；下一次仍从首次体验入口开始，首版不做跨会话剧情断点。
- 完成后再次点击直接正文；“重播体验”始终可选，重播退出不抹掉原完成记录。
- 打开体验暂停宏观历史时钟；退出／完成后宏观播放仍暂停，用户自行继续。临时打开人物／材料浮层只暂停当前剧情，不重置。
- 无 WebGL、资源故障、减少动态或需要无三维操作的用户，使用同一脚本的等价图文分步体验，保留两个必要互动与完成按钮。
- 热点均有键盘和文字列表替代；环顾不是唯一取得必要信息的方法。字幕不依赖声音，静音不影响完成。
- 没有已审核降级脚本时明确暂不可用，不能用空白页面、故障或“下一步”次数冒充完成。

**sn-01：查看地形与行进见闻。** 热点为 `sn-hotspot-terrain` 与 `sn-hotspot-account`，分别打开地形说明和历史材料。所有精确数值必须有据；当代照片拍摄条件不被当作历史天气。

**sn-02：辨别演绎效果。** 题目聚焦“程序生成的雪雾和背景音，能否单独证明当时确切天气／声响”。提交后解释场景效果与历史证据的区别，并链接本事件实际资料；确认解释后继续。

最小场景元素：来源明确的山体关系或清楚标注的局部艺术化环境、路径观察镜头、材料热点和字幕。不给观众设置会改写真实结局的体力、饥饿或死亡分支。

### 8. E06 穿越草地：环境与补给资料观察

experienceId：`exp-crossing-grasslands`。

### 9. 普通事件、地点、人物和完成后的正文

- 六主题之外的事件默认直接正文，除非后续明确增加重点体验并更新标准。
- 六主题关联子事件是否共用门槛由唯一映射规定；不能不同入口各弹一份重复体验。
- 地点正文包含历史名称、现代对照、事件关联、精度和材料性质；缺坐标仍可从目录访问。
- 人物动漫图必须与同一人的真实照片配对、分别说明与署源。无可用真实照片先文字展示并列缺口；不拿绘画／生成图伪装真实照片。
- 重点主题的正文必须独立完整：背景、经过、结果／影响、关联人物地点、来源及局限；体验完成后可直接读文，不依赖视频才能理解。
- 真实历史照片与当代纪念照片不混标；动漫／AI 图注明制作属性。使用条件不明的素材不发布。
