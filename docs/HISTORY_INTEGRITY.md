# 历史真实性与地图真实性

## 八条红线

1. 真实历史不可改写：重大事件、日期、人物、部队、会议、战役结果和行动顺序必须有核验史料。
2. 地图路线不可推测：禁止通过插值、平滑、最短路径、现代路网或 AI 填补证据缺口后作为真实行军路线。
3. 空间精度不得伪造：真实／近似／示意／未知分开记录。未知坐标为 null，不自行生成坐标。
4. 历史人物不得虚构言行：讲话、家书、电报、命令、档案须可溯源；摘引和编辑概述应区分。
5. 教学模拟不得改变历史：虚构观察者可作为视角，不能改变真实进程与最终结果。
6. AI 内容必须标注：艺术生成画面只能称“艺术再现／AI 生成”，不得称历史照片、档案或真实影像。
7. 正式内容须经人类复核：至少两名不同成员独立核验，AI 不得签署审核或改写结论。
8. 保存来源授权、另核地图合规：历史资料、地图、字体、音频、图片、模型与加工结果都须保留来源、权利及适用限制。公开地图展示另由人员核查适用规范。

## 从候选到发布

1. B 登记来源：`docs/sources/` 保存可查书目／官方链接、页码、原始摘录位置、获取日期、支持范围、局限与授权。先建立 draft + unpublished 的 SourceReference，不猜来源。
2. 录入候选：在 dataset.json 中添加 draft + unpublished 事件或路线。事实、编辑概述、艺术再现、教学模拟由 contentType 明示；路线按证据强度设置模式。
3. 提交 PR：附来源记录及 `docs/history-review/` 的审核工作单，记录争议、空间原始坐标系、转换方式、几何证据、权利和地图展示核查事项。进入 in_review。
4. 两名不同真人逐项核查：每人用自己的 GitHub 账号在 PR 中写明“同意发布 + 记录 ID + 证据范围”，并留下可定位链接。reviewerId 使用稳定的 GitHub 登录名，不能以不同别名重复计数。审核者有疑问即要求修改，不因机器通过而默认同意。
5. 由人员依据真实复核结果维护 reviews、reviewedBy、reviewedAt，设为 reviewed，再显式设 published。审核者和 C 核对记录与实际评论一致；Codex 不代填真人签署。C 只在完成真实双人复核后合并。
6. CI 再检查结构、来源关联、坐标、路线模式与两人复核字段。发布层只读取 published。无来源或不满足门槛的数据不进入正式界面。

同一内容的两人可以为 A/B/C 中任意两位；作者可为其中一位，但另一位必须独立核查。同一账号不能计两票。不要在模板中提前填 approved/reviewed。GitHub 对 PR 作者的原生批准限制不替代本流程的两份内容复核声明。

## 撤回与修订

发现问题先由人工撤回发布或新增 changes_requested 记录，保留旧复核记录。内容变更后旧审批失效：退回 unpublished + in_review，通过新 PR 重新双人核查。不要沿用旧审批，也不要覆写旧结论。来源权利或地图展示条件不清楚时保持不发布，记录待解决事项。

## 路线证据要求

实线必须具备明确支持几何的证据，至少两个合法坐标，有来源且 reviewed。不以“两个历史地点均正确”推导中间行军轨迹。仅确认地点用 points；宏观示意用 schematic + dashed，并持续显示“宏观示意，非真实行军路线”；证据不足只允许 hidden。A 保留坐标系、投影、高程基准、转换方法与误差说明，不能把现代地形包装成历史地形。

## 机器门禁的边界

Zod、CI 和构建能拒绝格式错误及不满足发布门槛的数据，不能验证史实、资料真伪、人员身份或授权充分性。`reviewerType: human` 是记录声明，不是身份认证。真正的复核依赖可核查证据、人员评论与 C 的合并审查。

正式数据目前为空。fixtures 不进入应用，也不作为正式史料；测试中对审核字段的内存模拟不是人工核验结果。
